# Doctor Gemini Dark Polish Design

## Background

医生端当前已经是深色主题，但整体仍偏“深蓝卡片系统”：大卡片、输入框、工作流面板和事件流里存在较多亮蓝/亮青硬边框，阴影和描边共同制造了偏重的轮廓感。和 Gemini 式暗色界面相比，当前页面的边界过多、绿色状态面积偏大、层级更多依赖线条而不是块面色差，导致界面不够冷静、通透和高级。

本次设计方向已确认采用 **A：Gemini 式黑底极光**。目标不是复制 Gemini，而是吸收它的视觉方法：近黑背景、多级暗面、少量冷蓝高亮、中心弥散光，以及更克制的边界处理。

## Goals

- 将医生端从“深蓝硬边框驾驶舱”调整为“近黑极光临床工作台”。
- 砍掉大卡片、对话、执行计划、事件流等区域的刺眼硬边框，改用暗色块面层级区分内容。
- 建立清晰的多级底色：页面底层、卡片层、输入框/小组件层各自有明确亮度差。
- 增加低透明蓝色弥散光，提升科技感和空间感，但不干扰临床信息阅读。
- 收敛绿色使用面积，只保留必要的小状态点；核心交互和激活态统一为冷蓝。
- 提升文字和图标对比度，让主信息更亮、辅助信息更自然地融入深色底。

## Non-Goals

- 不改医生端业务结构、导航结构、接口、状态机、流式会话、数据库逻辑或多模态业务逻辑。
- 不把患者端改成暗色；患者端继续保持已实现的白底类 GPT 风格。
- 不引入 3D、动画库或新的视觉框架。
- 不做大范围组件重构；优先通过 theme token 和医生端主题覆盖完成。

## Scope

本次视觉优化覆盖所有使用 `doctor-cockpit` 主题的医生端页面：

- 医生会诊工作台：三栏布局、患者摘要、病患部位、上传记录、对话区、工作流、执行计划、引用资料、事件流。
- 患者数据库页：历史病例工作台、表格、筛选、分页、详情卡片。
- 多模态分析页：影像/病理/实验室卡片、分组面板、动作按钮、状态信息。

患者端 `patient-care` 主题不在本次改动范围内。

## Visual Direction

### 1. Near-Black Page Base

医生端最底层背景改为接近纯黑：

- Body / app shell base: `#090A0F`
- 目的：去掉普通深蓝底带来的“旧后台系统”感，让页面更冷、更安静，也为蓝色极光提供更干净的承托。

### 2. Multi-Level Elevation By Surface Color

使用块面色差表达层级，而不是靠硬边框表达边界：

- 卡片层：`#12141C`
- 中心对话卡片/重点内容层：可使用 `#151821`
- 输入框、小组件、激活态容器：`#1A1D26`
- 悬停/选中态：只做轻微亮度变化和极弱蓝色 tint。

大面板默认不使用明显边框。必要的分割线只能用极低透明度白色或暗面差异，避免亮蓝/亮青描边。

### 3. Soft Aurora Glow

医生端主体区域背后增加一个蓝色弥散光层：

- 形态：大面积 radial gradient。
- 颜色：冷蓝，透明度控制在 `0.12-0.22` 区间。
- 位置：以会诊主区域后方为视觉中心，不能盖住输入框和数据阅读区。
- 技术约束：使用绝对定位或伪元素，`pointer-events: none`，`z-index` 位于内容下方。

目的：打破纯黑界面的死板感，建立 Gemini 式“屏幕有呼吸”的空间氛围。

### 4. No Hard Borders On Major Cards

以下元素在医生端主题下去掉硬边框：

- `.ui-card-clinical-panel`
- `.clinical-card`
- `.clinical-conversation-card`
- 工作流、执行计划、引用资料、事件流等内部卡片
- 数据库页和多模态页的主要面板

可保留的边界形式：

- 极低透明度的内部分割线。
- 焦点态的可访问性 outline。
- 少量微弱渐变边，只用于需要强调可交互状态的元素，不能成为页面主视觉。

### 5. Text And Icon Contrast

文字层级调整为深色界面下更锐利的对比：

- 主标题、核心指标、当前状态主文本：`#FFFFFF` 或 `#EAF2FF`
- 正文和普通标签：`rgba(255,255,255,0.72-0.86)`
- 辅助说明、空状态、placeholder：`rgba(255,255,255,0.35-0.56)`
- 禁用态：`rgba(255,255,255,0.26-0.32)`

图标颜色跟随同一套层级。避免细线图标被暗底吞掉；关键图标可以使用冷蓝，但面积要小。

### 6. Highlight Color Discipline

医生端高亮色统一收敛为冷蓝：

- 主交互按钮、发送按钮、导航激活态、进行中状态：冷蓝。
- 状态绿只保留小圆点或微小状态标记。
- “安全会话”“运行状态”等文字不再整段使用绿色，回归白/灰文本。
- 成功/警告/错误仍可保留语义色，但只用于必要状态，不扩散到普通卡片标题和装饰图标。

## Component Impact

### Top Navigation

顶部导航保持现有结构，但视觉上更轻：

- 导航容器与页面背景融合，去掉明显边框和重阴影。
- 激活 tab 使用暗面容器 + 冷蓝文字/短下划线或弱蓝 tint。
- 连接状态保留小绿点，状态文字改为白/灰。

### Consultation Dashboard

会诊三栏布局不变。左、中、右三列的面板都使用暗色块面层级：

- 左侧患者信息、病患部位、上传记录：无硬边框，靠 `#12141C` 与背景区分。
- 中间对话：作为主操作区域，可以略高一级，使用 `#151821`。
- 右侧工作流、计划、引用：保持信息密度，但去掉亮边，强化文本层级。

### Composer

输入框是医生端最核心的交互之一：

- 使用 `#1A1D26`，不使用亮边框。
- placeholder 使用半透明白。
- 发送按钮使用冷蓝，保持页面少数高饱和焦点。
- focus 状态需要可见，但应是柔和蓝色 glow 或 outline，不是刺眼边框。

### Workflow And Plan Panels

工作流和执行计划应更像暗色控制台信息块：

- 计划行使用暗面差异或轻微 hover，而非硬线框。
- 进行中状态用冷蓝点/短条。
- 完成状态可以保留极小绿色点，但文字不大面积变绿。
- 阻塞/错误保留语义红/橙，使用面积受控。

### Event Stream

事件流继续保留控制台气质，但更贴近近黑系统：

- 背景使用页面底色或更深卡片色。
- 事件 chip 去边框，改为暗面块。
- 元信息使用等宽字体和半透明白。

### Database And Multimodal Views

数据库页和多模态页共享医生端主题：

- 表格、分页、筛选、详情面板都使用同一套暗色层级。
- 表格行 hover 可以用低透明冷蓝 tint。
- 多模态卡片去硬边框，图标和动作按钮减少绿色占比。

## Accessibility And Usability

- 深色主题下核心文本必须保持足够对比度，不能为了氛围牺牲可读性。
- focus-visible 必须保留，键盘操作不能失去焦点提示。
- glow 层不得造成点击遮挡，不得引入横向滚动。
- 移动端和中等桌面断点下，弥散光不能压过内容，也不能造成文字模糊。

## Acceptance Criteria

- 医生端主背景接近 `#090A0F`，不再是当前偏亮深蓝底。
- 医生端主要卡片默认没有亮蓝/亮青硬边框。
- 页面可见至少两级暗色块面层级：卡片层和输入/小组件层。
- 会诊页主体背后存在低透明冷蓝弥散光，且不影响点击。
- 顶栏、对话、工作流、执行计划、事件流、数据库、多模态页面都使用统一医生端暗色语言。
- 绿色状态面积明显减少，只保留必要的小状态点或语义状态。
- 患者端视觉不受影响。
- 现有医生端交互测试、样式契约测试、构建流程继续通过。

## Verification Plan

- 更新样式契约测试，锁定医生端 token、无硬边框、弥散光、绿色收敛、深色层级。
- 运行医生端相关单元测试，确认导航、工作台、数据库、多模态视图行为不变。
- 运行 `npm run build`。
- 启动前端后用浏览器检查医生端会诊页、数据库页、多模态页桌面和移动端截图，确认没有横向溢出、遮挡、文字对比不足或亮边残留。

## Open Decisions Resolved

- 视觉方向：采用 A，Gemini 式黑底极光。
- 改动策略：纯视觉主题优化优先，不改业务逻辑。
- 高亮策略：冷蓝为主，绿色仅保留小状态点。
- 边界策略：大卡片无硬边框，必要状态使用极弱 focus/hover 反馈。
